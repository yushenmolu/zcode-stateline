# zcode-token-stats

**ZCode 插件：实时统计 token 用量、缓存命中率与生成速度（最近完成请求口径）**——对话内自动统计行 + 智能贴边状态条双通道展示，另带 `/stats` 斜杠命令随时查报告。

> English in one sentence: A ZCode plugin that shows real-time token usage, cache hit rate and speed (duration/TTFT) per conversation — as an in-chat stats line plus a docked status bar, with a `/stats` command for full reports.

- 版本：0.9.5
- 许可：MIT
- 平台：Windows（ZCode 桌面版 + Python 3.10+，仅标准库，无第三方依赖）

## 功能特性

- **智能贴边状态条（主显示）**：无边框置顶深色小条，自动吸附在 ZCode 主窗口底部外沿并跟随窗口移动；ZCode **最小化时自动隐藏**，恢复即回来。切到其他程序**不会**隐藏（0.2.1 起完整条的显隐只由「ZCode 窗口存在且未最小化且矩形可得」决定，前台判定降级为只让贴边锚点退一级——旧版在这里 `SW_HIDE`，导致点一下小条它就自己消失），置顶但从不抢焦点。
  - **三区对话级布局（0.4.0 起，纯函数排版可单测）**：第一行 = 状态徽标（彩色圆角块）+ 当前对话名；第二行左 = **本轮统计**（耗时 / in / out / cache hit / 工具数 / 数字来源标注 / ⚡ 速度），右 = **会话累计**小号灰字（`in · out · hit`，0.9.4 起带上会话级缓存命中率，与本轮段同一公式 `cache_read / input`，只算本会话的 `completed` 行；`input` 为 0 时整段 `hit` 不出现，不显示「hit 0.0%」）。数字用等宽字体防跳字；超宽时的收缩顺序固定：截短对话名 → 缩间距 → 省略累计标注，**徽标与统计数字永不裁剪**。
  - **速度段（⚡ tok/s）**：显示在第二行「本轮统计」尾部（格式 `· ⚡ X.X tok/s`），**生成中与工具中都显示**（0.9.1）；数值为本地数据库**本轮窗口内**最近一条已完成交互调用的 输出 token ÷ 耗时（排除 subagent / compact / session_title 后台来源），即**本轮最近一次完成调用的平均速度**，并非当前生成流的实时速度。「本轮窗口」的左沿取**上一轮的收尾时刻**（数据库时钟，0.9.1 起；不再用落盘滞后的钩子时刻，见「工作原理 · 本轮窗口」），所以本轮第一次调用完成即有速度。本轮还没有任何完成的调用时显示「· 生成中…」占位（不借用上一轮的数字）；工具中且本轮尚无完成调用则不显示。轮次结束（转空闲 / 失败 / 已中断）后 **60 秒内仍保留最后已知值并标注「（上次）」**，超时或切换到别的会话即清空——db 行只在调用结束时落库，收尾后已无「当前」速度来源。悬停气泡显示口径。
  - **靠边收起**：双击状态条任意区域或右键 →「收起到边缘」，收成屏幕底部的迷你把手（`◐ 84.9%` 浓缩缓存命中率）；把手**悬停约 0.5 秒或单击**即展开回完整状态条（重新贴边）。收起状态持久化到配置（`collapsed` 字段），重启后保持；把手的显隐**不依赖 ZCode 窗口是否找得到**（0.2.0 与完整态彻底解耦：只在 ZCode 进程退出、或真句柄可查且已最小化时隐藏，句柄取不到就跳过最小化判定），切到其他程序同样不隐藏，可拖动且不出屏。
  - **按当前对话各自统计**：状态条跟随当前活跃对话，显示**该会话自己**的累计数据；子代理（subagent）会话一律过滤，不串数据。
  - **可拖动**：按住任意区域左键拖到任意位置（自动钳制在屏幕内）；拖动后停在原处，右键 →「重新贴边」恢复自动跟随。
  - **悬停解释（tooltip）**：悬停各指标约 0.4 秒弹出气泡解释含义，截断的模型名/会话标题显示完整值。气泡**永远落在小条外侧**（0.9.4）：优先小条正上方、放不下退到正下方、横向跟随指针并夹进工作区——旧版按「指针右下」摆放再被工作区下缘回夹，几行高的气泡正好盖住它要解释的那行数字（用户反馈「详细信息框跟主显示框冲突」）；文案同时收紧到 200 字以内、换行宽 520px（最长的本轮气泡实测 532x116）。状态徽标的 tooltip 还带**本轮的确凿证据**（0.9.2）：工具中 = 工具名 + 已跑多久；出错 = 数据库里的 `error_type`（含工具报错条数、上下文是否溢出）；已中断 = 手动打断还是非用户取消。空闲时不带上一轮的失败原因（提示不是档案）。**本轮段的 tooltip 另带一行请求级画像**（0.9.4）：「本轮 n 次请求，其中冷读 k 次」——命中率按 token 加权，一轮里一次冷读（几乎整份 prompt 重新计费）就能把只含两次请求的本轮砍掉一半，所以「49.7%」配着「2 次请求，其中冷读 1 次」才是完整的一句话；`k=0` 时显示「无冷读（每次调用都命中了缓存）」。冷读判定 `COLD_READ_RATIO = 1%`：某次调用的 `cache_read_input_tokens < input_tokens × 1%`，阈值取在实测双峰的波谷里（本机 9386 条非后台 completed 调用：16.6% 落在 <1%、1%~5% 只占 0.4%、75.4% 落在 ≥90%），往任一侧挪一档结论都不变。取不到计数时该行不出现，只留固定说明。
  - **右键「显示项」菜单**：10 个指标开关直接勾选切换，立即生效并自动写回配置文件。
  - **低延迟数据源**：每约 1 秒只读直查 ZCode 本地数据库三张表——`model_usage`（模型调用**完成**即落库）给本轮数字与速度，`turn_usage`（轮次**结束**才落库）给权威结局，`tool_usage`（工具**开始**即落库，0.9.2）给「工具中」的实时证据；jsonl 记录仅作兜底。
  - **状态徽标 + 数据库速度（0.6.0 起，0.9.0 重写判定，0.9.2 补工具证据）**：状态徽标（空闲 / 生成中 / 工具中 / 出错 / 已中断）由三路证据共同判定——**钩子时序**（`status-state.json`，UserPromptSubmit / PreToolUse / PermissionRequest / PostToolUse / PostToolUseFailure / Stop 写入，0.9.0 起**按会话分片**，多窗口并发不再互踩）给出「当前活动阶段」；**数据库轮次行**（`turn_usage` 只在轮次结束时落库）给出「本轮已结束」的权威结论和 error / cancelled 结局（收尾后 20 秒内显示红「出错」/ 灰「已中断」，之后转空闲）；**工具行**（`tool_usage` 在工具一开始就落 `status='running'` 的行，0.9.2）给出「这一把工具还在跑」的实时证据——一把工具实测能跑 154 秒以上，其间另两路信号全部过窗，没有这一路就会既显错状态、又认不出当前是哪个会话。工具中徽标内联工具名（`🔧工具中·Bash`）。平台没有 SessionEnd / 中断钩子，Stop 漏写时不再挂 120 秒假「生成中」。生成中 ↔ 工具中之间有 2 秒最小驻留去抖，一轮几十次的工具往返不再让徽标蓝绿高频闪。生成中与工具中时第二行「本轮统计」尾部显示 `· ⚡ X.X tok/s`，数值限定在**本轮窗口**内最近一次已完成的交互调用（排除 subagent / compact / session_title 后台来源），本轮还没有完成的调用时显示 `· 生成中…` 占位而不借用上一轮的速度；轮次收尾后 60 秒内仍保留最后已知值并标 `（上次）`，换会话立即作废；本轮统计数字本身同样是本轮 `model_usage` 的实时聚合（尾部标 `· 实时`），本轮尚无落库数据时明确标 `· 上一轮`；本轮已有工具调用时追加 `· 工具 N`，其中报过错再追加红字 `· 错 M`（N=0 时整段不出现，不显示「工具 0」）。**实时生成流（0.3.0 的 SSE 反代 + `live_stream.json`）自 0.6.0 起停用**：本地代理不再默认启动（其钩子已从注册表移除），状态栏不再读取 `live_stream.json`；代理代码（`proxy_server.py`）保留在插件中，仅作为可选遗留组件，状态栏不再消费其数据。配置开关 `show_live`（默认 true，右键「显示项」可关闭）控制状态徽标与整段速度显示（含 `· 生成中…` 占位），`show_speed` 只关掉 ⚡ 数值段。
- **对话内自动统计行（兜底显示）**：会话启动与每轮提问时通过钩子注入上下文，模型在每次回复末尾自动附一行固定格式的统计；状态条不在时也有数字可看。
- **每轮 Stop 自动记录**：每轮结束自动把该会话新增的已完成调用聚合为一行 JSON，追加到 `token-stats.jsonl` 长期档案（幂等，重复触发不产生重复行）。
- **`/stats` 斜杠命令**：会话内输入 `/stats [会话|历史|模型|缓存|速度]` 输出统计报告。
- **配置热加载**：`statusbar-config.json` 保存后约 1 秒自动生效，无需重启；坏 JSON 不崩溃不丢配置。
- **只读 + 全本地**：对 ZCode 数据库全程只读（`mode=ro` + `PRAGMA query_only=ON`），不上传任何数据、无网络访问。

## 安装

### 方式一：ZCode UI 安装（推荐）

1. 把本仓库放到本机任意目录（或 clone 下来）。
2. 打开 ZCode → **设置（Settings）** → **插件管理（Plugin Management）** → **发现（Discover）**。
3. 点 **+** 添加本地市场，选择一个包含本插件 `.zcode-plugin/plugin.json` 所在目录层级的本地市场目录（ZCode 本地插件市场即插件缓存目录 `%USERPROFILE%\.zcode\cli\plugins\cache\local`，方式二脚本会自动把文件放进去）。
4. 在发现列表中找到 **zcode-token-stats** → 点 **Get（获取）** 安装。
5. 到 **已安装（Installed）** 页确认插件为**启用（enabled）**状态。
6. **完全退出并重新启动 ZCode**，钩子、`/stats` 命令与状态条即生效。

### 方式二：双击 install.cmd 一键安装

1. 确认已装 Python 3.10+（在 PATH 中，或设置 `PYTHON_BIN` 环境变量指向 python.exe）。
2. 双击项目根目录的 `install.cmd`（想先预览会发生什么，先在命令行跑 `install.cmd /dry`）。
3. 脚本会自动：复制插件文件到插件缓存目录 → 注册安装记录到 `installed_plugins.json`（先备份原文件）→ 在 `config.json` 中启用插件（先备份原文件）。
4. **完全退出并重新启动 ZCode**。

> ZCode 数据目录不在默认位置时，设置环境变量 `ZCODE_HOME` 指向你的 `.zcode` 目录后再运行。

## 使用

### 贴边状态条

- ZCode 会话启动时自动拉起；**如果重启后小条没出现**，双击运行 `scripts\docked_statusbar.py` 或手动运行 `hooks\ensure-docked-statusbar.cmd` 兜底启动（`statusbar.pid` 防多开，不会起两条）。
- **随 ZCode 一起关闭**（0.9.3）：每拍查进程表，进程表里再没有 `ZCode.exe` 且连续缺席满 5 秒，小条就自行退出并清掉 `statusbar.pid`（收起态的小把手同样退）。最小化 / 收进托盘不触发退出（那时宿主进程还在，只是窗口拿不到 -> 隐藏）。ZCode 升级 / 重装时若新旧进程交接超过 5 秒，小条会退掉再由新会话的启动钩子重开。
- 点右上角 **×** 或右键 →「退出 statusbar」关闭。
- 命令行验证数据读取（不弹窗）：`python scripts/docked_statusbar.py --once` 输出统计 JSON，除展示文案外还给出判定依据，便于对照数据库排查：`status`（状态徽标结论）、`source`（会话身份由哪路信号胜出：mark / status / resume / db / tool / jsonl）、`statsSource`（累计数字来源：db 真实聚合 / jsonl 兜底）、`recentNote`（是否需要在文案上标注「最近会话累计」）、`sessionId`、`speedTokPerSec`（最近一次完成请求速度）与 `speedAvgTokPerSec`（会话平均速度，无数据为 `null`）、`version`（运行中的代码版本）、`recentTurn`（本轮 `turn_usage` 聚合，含 `toolCallCount` / `toolErrorCount` 与 `activeTool:{name, runningMs}`——正在跑的那把工具及其已跑毫秒数；0.9.4 起另含 `modelCallCount` / `coldReadCount`，即状态条 tooltip 上「本轮 n 次请求，其中冷读 k 次」那两个数）。
- 可选参数：`--data-dir DIR`（数据目录）、`--db-path PATH`（ZCode 数据库路径）、`--interval-ms MS`（刷新间隔）、`--config PATH`（配置文件路径）。

### /stats 命令

会话内输入 `/stats`、`/stats 历史`、`/stats 模型`、`/stats 缓存`、`/stats 速度` 查看对应报告。其中「速度」为耗时与首字延迟统计（`avg_duration_ms`、`avg_ttft_ms`），与状态栏的 tok/s 口径不同。

### 配置（statusbar-config.json）

配置文件默认位于数据目录 `%USERPROFILE%\.zcode\cli\plugins\data\local\zcode-token-stats\statusbar-config.json`（首次启动自动生成）。**推荐直接用右键菜单切换**；手改文件约 1 秒内热加载生效。

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `show_model` | `true` | 第一行显示模型名 |
| `show_session` | `true` | 第一行显示会话标题 |
| `show_avg_duration` | `true` | 第二行显示平均耗时 ⏱ |
| `show_input` | `true` | 第二行显示输入 token 累计（in） |
| `show_output` | `true` | 第二行显示输出 token 累计（out） |
| `show_cache_read` | `true` | 第二行显示缓存读取 token（cache read） |
| `show_cache_hit` | `true` | 第二行显示缓存命中率（绿色，含微型进度条）；0.9.4 起同一个开关也控制右侧会话累计段的 `hit` |
| `show_speed` | `true` | ⚡ 数值段开关（0.9.1 起真的生效）：生成中 / 工具中在第二行「本轮统计」尾部显示 ⚡ X.X tok/s（最近一次完成回复的输出 token ÷ 耗时；小号灰字，0.4.3 起不再用橙色主显示） |
| `show_reasoning` | `false` | 第二行显示思考 token（reasoning，紫色） |
| `show_live` | `true` | 状态徽标与生成中速度段的显示开关（0.6.0 起，默认开；0.3.0 的实时流视图已停用） |
| `collapsed` | `false` | 状态条收起为底部迷你把手（双击/右键收起，悬停/单击展开；重启保持） |
| `refresh_ms` | `1000` | 刷新/贴边轮询间隔毫秒（250–60000） |
| `theme` | `"dark"` | 主题（当前仅 dark） |
| `enable_uia_tab_probe` | `false` | 实验项：用 Windows UIA 读 ZCode 标签栏标题，反查数据库得到「当前标签是哪个会话」，作为会话身份的第 6 路信号。**当前 ZCode 实测无效**（UIA 树已可达、内容也暴露，但 10 个会话行无一被标为选中（IsSelected 为真的那批全是消息正文段），探测恒返回 None，见「已知限制」），而且单次实测 85ms——开着只会每 3 拍多卡 85ms，换不到任何信号。0.9.2 起真的读热加载后的配置（此前只有改源码常量才生效） |

### 右键菜单

- **显示项**：10 个指标开关（模型/会话/耗时/输入/输出/缓存命中/缓存读取/速度 tok/s/推理/状态徽标），勾选即显隐，立即重画并自动写回配置。
- **重新贴边**：拖动过后恢复自动跟随 ZCode 窗口底部。
- **收起到边缘**：把状态条收成屏幕底部迷你把手（双击状态条同效）。
- **退出 statusbar**：关闭状态条。

## 系统要求

- Windows（Win32 API + tkinter，其余平台未适配）。
- ZCode 桌面版。
- Python 3.10+，仅标准库（json / sqlite3 / tkinter / ctypes），无需 pip 安装任何包。
- 默认假设 ZCode 数据目录位于 `%USERPROFILE%\.zcode`（数据库 `~\.zcode\cli\db\db.sqlite`）；不一致时用 `ZCODE_HOME` 环境变量（安装脚本）或 `--db-path` 参数（状态条）覆盖。

## 工作原理

```
会话启动/提问 ──► hooks.json ──► mark-session.cmd ──► mark_session.py ──► current-session.json（当前会话标记）
                            └─► inject-context.cmd ──► inject_context.py ──► 注入统计行上下文（additionalContext）
                            └─► ensure-docked-statusbar.cmd ──► docked_statusbar.py（贴边状态条，每秒只读刷新）
ZCode 钩子事件（UserPromptSubmit/PreToolUse/PermissionRequest/PostToolUse/PostToolUseFailure/Stop）──► status-event.cmd ──► status_event.py ──► status-state.json（按会话分片 v2）──► 状态栏徽标
本地 db ──► 只读直查 ──► turn_usage 行给出「本轮已结束」权威结论（失败/已中断/空闲）+ 本轮 model_usage 实时聚合与速度
                    └──► tool_usage 行（工具一开始就落 running 行）给出「这一把工具还在跑」的实时证据：状态续期 + 会话身份信号（0.9.2）
（0.6.0 起停用）proxy_server.py（本地 SSE 反向代理 18080→8080，遗留组件，状态栏不再消费 live_stream.json）
每轮结束 Stop ──► hooks.json ──► on-stop.cmd ──► record_usage.py ──► 只读聚合 db ──► 追加 token-stats.jsonl
手动查报告 ────► /stats ──► db_stats.py ──► 只读聚合 db ──► 会话/历史/按模型统计
（可选遗留）模型请求（经 baseURL 改 18080 后）──► proxy_server.py ──► 透明转发 ──► 127.0.0.1:8080（ZCode 本地模型服务）
```

- **宿主存活分成两条判定（0.9.3）**：**显隐**看窗口——`find_zcode_window()` / `_zcode_process_alive()` 按可见顶层窗口的 exe 路径含 `zcode` 判定，拿不到就把小条 `SW_HIDE`（最小化、收进托盘、句柄瞬时取不到都走这条，只藏不退）；**退出**看进程表——`zcode_app_running()` 用 `CreateToolhelp32Snapshot` 遍历，exe 名精确等于 `zcode.exe` 即算宿主还在，连续缺席满 `ZCODE_GONE_QUIT_MS=5s` 才 `root.quit()`。不复用窗口那条判退出：它链上挂着 `OpenProcess` / `QueryFullProcessImageNameW` 等可瞬时失败的调用，用它判退出等于宿主活着时随时可能把小条杀掉；进程表快照本身失败一律 fail-open（判存活）。阈值按时长而非拍数，因为 `refresh_ms` 可在 250–60000 之间配置。
- **数据库只读**：所有 SQL 经 `sqlite3.connect("file:...?mode=ro")` + `PRAGMA query_only=ON`，绝不写 ZCode 数据库。
- **统计口径**：请求数对全部行计数；token/耗时聚合仅 `status='completed'` 行；缓存命中率 = `cache_read / input`（db 的 input 已含 cache_read 部分）；行级排除子代理调用。
- **命中率对不上中转面板是总体不同（0.9.4）**：公式两边一致（`cache_read / input`），差别在**聚合哪一批调用**——中转面板的小时曲线含**全部流量**，而 subagent 占其中的大半（本机一个 145 行的时间窗里 134 行是 subagent）且命中率普遍更高（同窗 subagent 86.2% vs 主会话 51.2%；全天 85.0% vs 65.9%）。状态条只看**当前会话**，所以「中转 82.2% / 这边 49.7%」不是算错。为此给两个自查数：右侧累计段的 `hit`（本会话全轮次的加权命中率，同公式）和本轮 tooltip 的「本轮 n 次请求，其中冷读 k 次」。另注意**本轮段与累计段的后台口径刻意不同**：实时本轮聚合排除 `subagent` / `compact` / `session_title`，而权威 `turn_usage` 行与会话累计都**含** `compact` / `session_title`（本机 12 个主会话轮次对账：`turn_usage.input_tokens` 与窗口内**全部** `model_usage` 行之和 12/12 完全相等）——所以请求级画像查询也不过滤 `query_source`，否则会出现「2 次请求无冷读」配着 18% 命中率的误导画面。
- **幂等记录**：每会话独立时间戳游标（`state.json`），只聚合上次记录之后的调用，重复触发不产生重复行。
- **当前会话判定**（fail-closed，绝不猜）：信号池 = `current-session.json` 新鲜标记（30 秒）+ `status-state.json` 最新分片（60 秒）+ 日志 `session.resumed`（600 秒）+ 数据库 180 秒内活跃主会话 + **仍 running 的 `tool_usage` 行（起点 600 秒内，0.9.2）** +（默认关）UIA 标签标题反查，各带**真实发生时刻**参与竞争，胜出者粘滞为当前会话（陈旧信号不得顶掉正在用的会话）；平局按 mark > status > resume > db > tool > uia 定序；全无信号才回退 jsonl 最新主会话；「最近会话累计」标注在**身份来源或数字来源任一路取自 jsonl** 时出现（`--once` 里 `source` / `statsSource` / `recentNote` 就是这三项判定的输出）；子代理会话每步排除。
- **状态判定（0.9.0，0.9.2 补工具证据）**：先权威后推断——`turn_usage` 行的收尾时刻不早于最后一条钩子事件即「本轮已结束」，直接给 idle / error / cancelled（**例外**：收尾之后又开了一把仍未收尾的工具 = 新一轮已在跑，显「工具中」）；否则按事件新鲜窗口（生成中 120 秒、工具中 900 秒）推断，长生成靠「本事件之后确有模型调用完成」续期，工具则由仍在 running 的 `tool_usage` 行续期（**前提**：该行起点晚于最后一条事件，且未超 600 秒采信上限——进程被强杀会留下永不收尾的 running 行，本机实测最老一条挂了 27 天，不设上限就会永远显「工具中」）。busy 族内切换有 2 秒最小驻留去抖；进出 busy 族立即生效（停了要立刻显停）。
- **本轮窗口（0.9.1）**：实时聚合与速度的左沿取**上一轮 `turn_usage` 行的收尾时刻**（会话首轮不设下界），归属判定也比该行的收尾时刻。为什么不用钩子落盘的 `turn_started_at`：钩子是宿主异步拉起的进程，实测本机 UserPromptSubmit 写盘时刻比该轮 `started_at` 晚 **17.0 秒**，滞后量还随负载变化（同一文件里 Stop 只晚 0.5 秒），0.9.0 的 15 秒固定容差会被踩穿——本轮首次调用被排除出窗口，明明在跑本轮却标「· 上一轮」，速度也要晚一个调用才出现。改用数据库自身时钟后，比较的两侧来自同一时钟。本机 1513 个已收尾轮次回放：旧规则会漏掉 358 轮（23.7%）的本轮首次调用，新规则一条不漏。

## 已知限制

- 仅支持 Windows；多显示器 / 非 100% DPI 缩放未实测。
- **纯切换会话标签但不发消息时状态条不跟随**（拿不到可靠信号，不是判定链缺陷）：ZCode 没有「标签切换 / 窗口聚焦」钩子，`current-session.json` 只在发消息时写；数据库里也不存在 UI 状态（哪个标签在前是渲染层的事）。UIA 这条路 0.9.2 重新真机核过，**结论和 0.9.1 之前写的相反**：Electron 内容确实已暴露给 UIA（主窗口树里 189 个 Button、84 个 ListItem，其中 10 项的 Name 就是侧栏会话标题+相对时间），但仍指认不出「当前是哪个会话」，两道闸各断一次：① 有 IsSelected 的 63 项全是消息正文段，10 个会话行无一选中（含正开着的那个）；② 会话行 Name 是「标题+相对时间」拼的，而标题反查只做「精确相等」和「截断标题按前缀 LIKE」，方向相反命中不了。所以 `probe_active_tab_title` 仍恒为 None，`enable_uia_tab_probe` 继续默认关（单次实测 85ms）。将来要启用得同时换判别量（SelectionItemPattern / AutomationId / 类名）并加一档「Name 以标题开头」的反向匹配。发一条消息后立即跟随（新会话的模型调用 / 工具行是最强信号）。
- **工具证据的两处边界（0.9.2）**：一把工具真跑过 600 秒时不再采信其 running 行，会回落成空闲——因为进程被强杀留下的僵尸行永不写 `completed_at`（本机实测最老一条挂了 27 天），宁可为低估不永远挂蓝标；老版本 ZCode 没有 `tool_usage` 表时该路信号自动缺席，判定链退化为 0.9.1 的行为（不报错、不猜）。
- 对话内统计行依赖模型遵循注入的格式指令，偶发遗漏属正常。
- Stop 触发时最后一笔调用可能仍在途，该轮数据由游标在下一轮补齐（延迟而非丢失）；进程被强杀时该轮统计缺失。
- 缓存命中率为输入侧口径，与厂商账单口径（含 cache_creation）可能不一致。与中转/上游面板的数字也不会相等：那边含全部流量（subagent 占大半、命中率更高），这边只算当前会话，见「工作原理 · 命中率对不上中转面板是总体不同」。
- **本轮数字在收尾那一拍可能小幅跳变（0.9.4 记录，非缺陷）**：生成中读的是实时聚合（排除 `compact` / `session_title` 后台调用），收尾后换成权威 `turn_usage` 行（含它们），两者的 in / cache hit 因此会有一点差值。同理，tooltip 的请求级画像取不到计数时（无数据 / 读库失败）整行不显示，不会拿别的轮次的计数凑。
- **冷读是判定阈值而非平台字段**：`COLD_READ_RATIO = 1%` 是本地实测双峰波谷处的人工阈值，db 里没有「这次是不是冷读」这一列；上游若改变缓存写入策略（比如开始小片段缓存），阈值需要重新核。
- 状态栏速度不是当前生成流的实时速率，而是本地数据库本轮窗口内最近一条已完成交互调用的 输出 token ÷ 耗时（本轮最近一次完成调用的平均速度）；本轮尚无已完成调用时显示「· 生成中…」占位，收尾后 60 秒内显示的是最后已知值并标「（上次）」。实时流（0.3.0 的 SSE 反代 + `live_stream.json`）自 0.6.0 起停用：代理不再默认启动（钩子已从注册表移除）、状态栏不再消费其数据，代理代码保留为可选遗留组件。
- 失败 / 已中断徽标只在轮次收尾后 20 秒内显示（提示不是档案），之后转空闲；期间的完整原因看 `turn_usage.error_type` / `cancelled_by_user`（0.9.2 起徽标 tooltip 直接把它显示出来，不必查库）。
- 轮次收尾后的归属判定比的是「turn 行收尾时刻不早于本轮 `turn_started_at`」，而本轮的 turn 行由它**最后**一次模型调用落库：一轮在十几秒内结束、且钩子落盘又滞后时，它仍可能被标成「· 上一轮」（少一次权威本轮值，不显示错数字）。进行中那一路不受影响——实时聚合与速度的左沿取上一轮的收尾时刻，比较双方同为数据库时钟。拿本机 135 个会话 / 1513 个已收尾轮次回归过这套左沿：本轮的行**一条都没漏**（0 条被排除出窗口），代价是 24 个轮次里混进 201 条别的轮次的行（并发/排队导致的轮次交叠，任何按时间的窗口都区分不开），且只影响「实时」累计量，⚡ 速度取单条最新行不受影响。
- ZCode 升级若改 `db.sqlite` 表结构，SQL 需要相应调整。

## 常见问题

- **状态条没出现？** 双击 `scripts\docked_statusbar.py`，或运行 `hooks\ensure-docked-statusbar.cmd`；仍不行看数据目录下 `docked-statusbar-err.log`。
- **提示找不到 Python？** 安装 Python 3.10+（python.org，勾选 Add to PATH），或设置环境变量 `PYTHON_BIN` 指向 python.exe（无窗口版可再设 `PYTHONW_BIN` 指向 pythonw.exe）。
- **数字不更新？** 检查数据目录下 `stats.log`、`cmd-stderr.log`、`inject-stderr.log`、`mark-session-stderr.log`（正常应为空或只有少量跳过记录）；确认 ZCode 数据库在默认位置，否则用 `--db-path` 指定。
- **想彻底清空统计数据？** 停止状态条后删除数据目录 `%USERPROFILE%\.zcode\cli\plugins\data\local\zcode-token-stats`（卸载插件默认保留该目录）。

## 卸载

运行 `uninstall.cmd`（先 `uninstall.cmd /dry` 预览）：移除安装记录与启用项（均先备份）→ 删除插件缓存目录 → 重启 ZCode。统计数据目录默认保留，需要彻底清空再手动删除。通过 UI 安装的用户也可在 ZCode 插件管理页直接卸载。
